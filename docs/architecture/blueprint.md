# QR Restaurant Ordering App - Technical Blueprint

## 1) MVP Scope (Phase 1)
- Customer scans QR at table and opens ordering page.
- Customer views menu, adds items, places order.
- Kitchen screen receives new orders in realtime and updates status.
- Staff/cashier dashboard sees table orders and marks payment.

## 2) High-level Architecture
- Frontend (Web):
  - Customer App (mobile-first web)
  - Kitchen Screen (tablet/desktop web)
  - Staff Dashboard (desktop web)
  - Admin Dashboard (basic CRUD for menu/tables/users)
- Backend API:
  - REST API for CRUD and order flows
  - WebSocket gateway for realtime order/status updates
- Database:
  - PostgreSQL for transactional data
- Optional Infra (phase 2):
  - Redis for queue/cache
  - Object storage for menu images

## 3) Suggested Tech Stack
- Frontend: Next.js + Tailwind CSS
- Backend: NestJS + Prisma ORM
- Database: PostgreSQL
- Realtime: Socket.IO or native WebSocket
- Auth: JWT for staff/admin; signed table token for customer flow

## 4) Core Domain Model
- Table: physical table in restaurant
- Session: dine-in session bound to one table and time window
- MenuItem: product customer can order
- Order: one submit action by customer/staff
- OrderItem: line item in an order
- Payment: settlement for one table session

## 5) QR Design
QR payload URL format:
`https://your-domain.com/order?t=TABLE_CODE&s=SIGNATURE`

Rules:
- `t`: table code (e.g. T01)
- `s`: HMAC signature generated by server secret over table code (+ optional expiry)
- Backend verifies signature before allowing order creation.

## 6) Order State Machine
- `new` -> `confirmed` -> `preparing` -> `ready` -> `served` -> `completed`
- Cancel path: `new|confirmed` -> `cancelled`
- Payment state: `unpaid` -> `partially_paid` -> `paid` -> `refunded`

## 7) Realtime Events
- `order.created`
- `order.updated`
- `order.item.updated`
- `payment.updated`
- `table.session.closed`

## 8) Non-functional Requirements (MVP)
- P95 API response under 500ms for read endpoints
- Realtime propagation under 2 seconds
- Audit log for order status/payment changes
- Role-based authorization for staff/kitchen/admin

## 9) Delivery Plan
- Sprint 1: DB + API for menu/tables/orders
- Sprint 2: Customer ordering UI
- Sprint 3: Kitchen realtime screen
- Sprint 4: Cashier/payment + hardening
